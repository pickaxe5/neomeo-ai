# 너머 (Neomeo) — AI

> An async handoff layer that stitches each team's end-of-day into one project timeline.

팀마다 다른 '하루의 끝'을 하나의 프로젝트 시간축으로 잇는 비동기 인수인계 레이어입니다. 이 레포는 그중 **AI 요약·브리핑 파이프라인**을 담당합니다.

## 서비스 소개

시차로 흩어진 팀은 협업의 리듬을 잃는다. 질문 하나를 던져도 상대 팀이 출근할 때까지 하루를 기다려야 하고, 다른 팀이 그사이 무엇을 했는지는 서로 다른 언어로 쌓인 커밋 로그를 뒤져 직접 짜맞춰야 한다. 진행 상황은 흐르는데, 그 흐름을 읽는 비용이 팀마다 제각각이다.

기존 요약 도구들은 이 문제를 UTC 자정 같은 고정된 시각에 하루를 잘라 해결하려 한다. 하지만 고정된 경계선은 누군가에게는 늘 어긋난다. 어떤 팀의 하루는 항상 반토막 난 채로 요약되고, 정작 그 팀이 하루를 마무리하며 남긴 맥락은 두 개의 요약에 걸쳐 흩어진다.

너머는 요약의 경계선을 '하루'가 아니라 **각 팀의 업무 종료 시점**으로 잡는다. 팀마다 국가·타임존·업무시간·언어를 설정해 두면, 각 팀이 업무를 마치는 순간 그때까지의 GitHub 변경사항(PR·이슈·리뷰 코멘트)을 모은다. 이 사실들은 언어에 무관한 구조화 데이터로 정규화되고, AI는 그 데이터로부터 각 팀의 언어로 요약 카드를 **직접 생성**한다 — 한 언어로 쓴 요약을 옮기는 번역이 아니라, 같은 사실에서 각 언어의 카드를 따로 만들어 내는 방식이다.

이렇게 만들어진 카드는 크로스 타임존 타임라인에 시간순으로 쌓인다. 다음 날 출근한 사람은 개인 브리핑을 받는다: ①내가 답해야 할 것, ②내 작업에 영향을 주는 변경, ③팀 전체의 진행 상황. 남의 하루를 뒤늦게 재구성하는 대신, 이어받을 지점부터 시작할 수 있다.

## 이 레포의 역할

`neomeo-ai`는 너머의 **요약·브리핑 생성**을 담당한다. 수집·저장·화면은 별도 레포 [`neomeo-web`](https://github.com/pickaxe5/neomeo-web)이 맡고, 이 레포는 web이 넘겨준 0층 데이터를 입력으로 받아 1층 팀 요약 카드와 2층 개인 브리핑을 생성해 돌려준다.

데이터는 3개 층위로 흐른다.

- **0층 — 구조화 사실**: PR·이슈·리뷰 코멘트를 언어에 무관한 구조화 데이터로 정규화한 원본 사실 (web이 제공, 이 레포의 입력)
- **1층 — 팀 요약 카드**: 0층에서 각 팀의 언어로 생성한 요약 카드. 번역이 아니라 사실로부터의 직접 생성 (이 레포가 담당)
- **2층 — 개인 브리핑**: 1층 카드와 0층 사실을 개인 관점(답해야 할 것/영향받는 변경/팀 진행)으로 재구성한 브리핑 (이 레포가 담당)

## 디렉토리 구조

```
neomeo-ai/
├── prompts/    # 팀 요약 카드·개인 브리핑 생성 프롬프트
└── pipeline/   # 0층 입력 → 1층 카드 → 2층 브리핑 생성 파이프라인
```

## 로컬 실행

각 파트 스택 확정 후 추가 예정 (D1~D2).

## 협업 규칙

이 레포는 우리 서비스가 직접 수집·요약하는 **도그푸딩 대상**이므로, PR·이슈의 제목·본문 품질이 곧 데모 품질이다. 아래 규칙은 그래서 존재한다.

- **PR 제목**: `[파트] 무엇을 했는지 명확히` — 예: `[ai] 팀 요약 카드 생성 프롬프트 초안 추가`
- **이슈 제목**: PR과 동일 형식. 질문 이슈는 `[질문]` 접두어를 붙인다 — 예: `[질문] 카드 생성 시 코드 diff는 어디까지 넣나요?`
- **커밋 메시지**: 짧아도 무엇을 왜 했는지 알 수 있게 쓴다.
- 파트 표기: `front` / `back` / `ai` / `infra`
